# 调查回避分派数据约定

日期按本地自然日表示（`YYYY-MM-DD`），履历中的起止日均包含在有效区间（闭区间）。

`data/example.json`（人员）与 `data/cases.json`（案件）中的记录均为虚构业务样例。
字段名称与字段类型由 `contracts.py` 中的数据结构描述。原始记录按来源提供的顺序读取，
字段值不在读取时改写，仅做结构与取值校验。

## 人员记录（SourceRecord）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `person_id` | string | 人员编号，非空 |
| `qualifications` | string[] | 持有的岗位资质；可取值含 `site_tech`、`material_review` |
| `project_links` | object[] | 与工程的关系履历，见下 |
| `capacity` | int ≥ 0 | 可同时承担的案件分工数 |
| `region` | string | 常驻区域，用于跨区支援成本 |

关系记录（ProjectLink）：

| 字段 | 说明 |
| --- | --- |
| `kind` | `employment`（任职）/ `kin_declaration`（近亲属申报）/ `acceptance_signoff`（验收签署） |
| `project_id` | 关系指向的工程编号 |
| `effective_date` | 关系生效日：任职起始 / 申报受理 / 验收签署日 |
| `end_date` | 仅任职关系必填（任职结束日）；其余关系为 `null` |
| `evidence` | 来源证据编号，供关系版本核对 |

任职按 `[effective_date, end_date]` 与调查窗口做含端点重叠判定；申报与验收签署按
`effective_date` 单日是否落入窗口判定。三类关系分别判断，窗口外关系不产生回避但保留展示。

## 案件记录（CaseRecord）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `case_id` | string | 案件编号 |
| `project_id` | string | 被调查工程编号 |
| `window_start` / `window_end` | date | 调查窗口（含端点） |
| `region` | string | 工程所在区域 |
| `emergency` | `normal` / `urgent` / `critical` | 紧急程度，决定跨区代价权重 |
| `required_roles` | string[] | 必备岗位；必须同时包含 `site_tech` 与 `material_review` |

## 运行期数据

关系版本（`relation_version`）为人员全部关系记录规范化 JSON 的 SHA-256 前 12 位；
方案生成时固化所涉人员版本，确认时复核，调查中新登记的关系会使版本变化。
分工状态为 `active` / `removed`；意见状态为 `valid` / `needs_recheck`。
运行期状态保存在进程内存量中，重启后以数据文件重新装载。
